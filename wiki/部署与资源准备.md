# 部署与资源准备

本页给开发和运维人员使用。完整命令、变量和生产门禁仍以 `docs/deploy.md` 与 `docs/windows-production.md` 为准。

## 部署前准备

1. 安装 Docker Desktop 或兼容的 Docker Engine/Compose。
2. 为每个内部服务配置不同的服务密钥。
3. 配置 MySQL、MongoDB、Neo4j 的生产密码和持久卷。
4. 注入模型供应商、邮件和支付相关的必要变量。
5. 在构建 ModelService 前恢复模型资源。

## 下载模型资源

模型文件不进入 Git。通过进程环境注入 OSCA 只读凭据：

```powershell
$env:OSCA_ACCESS_KEY_ID = '<read-only access key>'
$env:OSCA_SECRET_ACCESS_KEY = '<read-only secret key>'
.\scripts\download-model-resources.ps1
Remove-Item Env:OSCA_ACCESS_KEY_ID, Env:OSCA_SECRET_ACCESS_KEY
```

恢复顺序为：已校验本地缓存、OSCA 主镜像、可选离线副本、固定远端版本。全部 19 个文件必须通过长度和 SHA-256 校验，包括新 NLI、旧 SBERT、旧 q 模型、tokenizer、词典和 `vocab.txt`。

完全离线部署可使用：

```powershell
.\scripts\download-model-resources.ps1 `
  -FallbackSourcePath D:\TrustedBackups\GalReview-ModelService-Resources
```

## Compose 启动

```powershell
docker compose -f compose.integration.yaml config --quiet
docker compose -f compose.integration.yaml up -d --build
docker compose -f compose.integration.yaml ps
```

默认栈包含 16 个服务。OCR 使用可选 profile；不需要 OCR 时不要启动。

## Wiki 静态部署

Wiki 的 Markdown 源位于仓库根目录 `wiki/`，图片、样式和脚本均在 `wiki/res/`。前端执行 `npm run build` 时会：

1. 构建 React 应用。
2. 读取 `wiki/*.md`。
3. 生成 `frontend/dist/wiki/*.html`。
4. 复制 `wiki/res` 到静态输出。

部署后访问 `/wiki/`。前端 Docker 构建上下文必须包含根目录的 `wiki` 和 `frontend`，当前 Compose 已使用根目录上下文及 `frontend/Dockerfile`。

## 健康检查

- Frontend：`/healthz`
- Gateway：`/readyz`
- ModelService：`/readyz` 必须显示 NLI、SentencePiece 和同义词资产为 `READY`
- PracticeService：readiness 中应显示 `modelInference=gateway:model-service`

服务健康不等于完整业务可用。发布前还应完成注册、非 OCR 上传、立册、题目生成、智能复习、判分、掌握度回写和 credits 结算的全链检查。

## 不应提交到 Git 的内容

- `backend/ModelService/Resources`
- 下载后的模型和词典
- OSCA、模型供应商、数据库和服务密钥
- 兑换码明文
- 构建产物和临时截图脚本
