# 服务架构

## 业务边界

千知万理以研习册为核心聚合。各服务各自拥有数据和规则，通过 Gateway 暴露统一接口。

| 服务 | 主要职责 |
|---|---|
| Gateway | 对外统一入口、鉴权转发、限流和服务身份 |
| AuthService | 注册、登录、会话、密码与管理员认证 |
| UserService | 用户资料与学习偏好 |
| CreditService | 余额、预留、实际结算和兑换码 |
| FileService | 文件、解析任务、规范化文本和来源区间 |
| PracticeService | 研习册、题库、答题、试卷、判分状态机和 SM-2 |
| KnowledgeService | 本册图谱、知识点关系、计划和掌握记录 |
| ModelService | ONNX、tokenizer、词典、资产门禁和逐事实推理 |
| GalGameService | 故事生成任务与不可变游戏包 |
| RenderService | 故事运行时、进度、事件和结果提交 |
| OCRService | 可选的图片及扫描件文字识别 |
| Frontend | 用户界面、同源 API 代理和静态 Wiki |

## 模型服务边界

ModelService 采用 API、Application、Domain、Persistence 四层，Application 使用 MediatR 和 CQRS。它只返回逐事实推理结果，不拥有题目聚合、correct、quality、SM-2 或掌握度。

PracticeService 通过 Gateway 调用 ModelService，不直接读取 ONNX 文件。模型缺失或低置信时，PracticeService 形成 `ABSTAINED`，不会改用编辑距离随意判错。

## 数据关系

资料属于用户；研习册引用一份或多份资料；知识图谱属于研习册；题目绑定本册知识点和资料来源；普通答题与故事答题都形成同一种掌握证据。

## 契约优先级

接口、状态、作用域和错误语义以 `docs/contract.md` 为准。部署步骤以 `docs/deploy.md` 为准。本 Wiki 面向使用者进行解释，不另行创造接口。
